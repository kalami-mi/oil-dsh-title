# 安装与验证

## 前提

- Windows 上的 DeepSeek Harness 桌面端。本插件在桌面端 `0.2.0-rc.2` 自带的运行时上开发和测试；DSH 会按 `package.json` 里的对等依赖（`@deepseek-ai/dsh-llm ^0.2.0-rc.2`）检查兼容性，不兼容的版本会跳过这个 bundle，并在“插件”页显示原因。
- 本机有 Node.js（只用于打包这一步；桌面端自己不需要它）。

## 安装（推荐：桌面端“插件”页）

1. 在插件目录里生成干净的安装目录：

   ```powershell
   cd C:\Users\ZHKJ\Documents\oil-dsh-title
   node scripts/pack.mjs
   ```

   输出 `dist\oil-dsh-title` 的绝对路径。这个目录只含 `package.json`、`cordis.patch.yml`、`lib/`、README、LICENSE，不含开发用的 `node_modules`。

   **重要**：桌面端用 pnpm 按路径安装，结果是指向这个目录的**链接**（`link:`），不是拷贝。安装后不要移动或删除它，否则插件会失效。想把它放到更稳定的位置，可以 `node scripts/pack.mjs --out C:\Users\ZHKJ\.dsh\plugins`，再用打印出的路径安装。

2. 打开桌面端，侧边栏选择 **插件**，点 **添加插件**，粘贴上一步的绝对路径（插件管理器只接受**绝对**本地路径），确认安装。安装过程中会显示 pnpm 输出。本插件没有运行时依赖（只声明对 Harness 自带包的对等依赖），本地路径安装用桌面端自带的 pnpm 离线验证通过。
3. 安装后它以组合包（bundle）出现在列表里。启用它。桌面端如果提示需要重启，就重启一次；开启了热重载的 profile 会立刻重组。
4. 想临时关掉：在插件页把 **整个 `oil-dsh-title` 组合包**停用（组合包开关）。组合包的补丁层随之撤掉，被它关闭的内置提供者 `session-title-llm` 自动恢复。不要只关组合包里的单独一行：那样内置提供者仍是关闭的，会没有任何提供者，标题退回“取前几个词”。

## 手动方式（不通过界面）

编辑 `C:\Users\ZHKJ\.dsh\profiles\desktop\package.json`：把 `dsh.profile.bundles` 末尾加上 `"oil-dsh-title"`，并把包放进该 profile 的依赖里（例如在该目录用桌面端自带的 pnpm 执行 `pnpm add <dist 绝对路径>`）。这条路径绕开了插件管理器对版本兼容的预检，仅在界面方式不可用时使用。

## 验证（按顺序，缺一不可）

程序测试、真实触发和桌面显示是三类不同的证据，不能互相替代。

1. **程序层**：`python scripts/extract-runtime.py "D:\DeepSeek Harness"` 后运行 `npm test`，应全绿。这只证明代码在真实运行时包上行为正确。
2. **装配层**：桌面端插件页里 `oil-dsh-title` 应显示已启用、没有错误标签；被跳过的 bundle 会带异常标签并给出原因。
3. **真实触发**：新开一个会话，发一条有实质内容的消息（例如“帮我修复邮箱注册的验证码过期问题”），等这一轮回答结束。几秒内侧边栏标题应变成「emoji 对象｜目标」。输入 `/title status`，看到：
   - `当前标题：…〔自动命名〕`；
   - `本会话最近一次：renamed｜…`；
   - `累计模型调用` 至少 1 次。
4. **保留与更新**：接着发一个仍属同一主线的补充，标题应保持不变（日志状态 `kept`）；明确转向新话题后应更新。发“好的”，`/title status` 里“免调用的确认跳过”应增加，而调用次数不变。
5. **保护**：在侧边栏手动改名，之后再聊几轮，标题不应被改回；`/title unlock` 后恢复。

如果第 3 步没有变化，依次检查：

- `/title status` 是否显示“已暂停”；
- `C:\Users\ZHKJ\.dsh\oil-dsh-title\logs\<会话ID>.jsonl` 最后一行的 `status`：`no_route` 表示找不到模型路由，需要在补丁里同时填 `provider` 与 `model`（见 [使用与边界](使用与边界.md#配置)）；`model_error`/`timeout` 表示命名请求失败，`detail` 里有原因；`invalid_output` 表示模型两次都没给出合规标题；
- 桌面端日志（`%APPDATA%\@deepseek-ai\dsh-desktop\logs`）里是否有以 `oil-dsh-title:` 开头的告警。

## 卸载

1. 在插件页移除 `oil-dsh-title`（会先取消选择该 bundle，再 `pnpm remove`）。
2. 因为关闭 `session-title-llm` 的补丁属于本 bundle 的补丁层，移除 bundle 后它一并消失，内置提供者自动恢复。
3. 数据目录 `C:\Users\ZHKJ\.dsh\oil-dsh-title` 可以直接删除，不影响 Harness。

已经写进会话日志的标题保持原样。

## 升级

修改代码后重新 `node scripts/pack.mjs`：因为安装的是指向该目录的链接，打包会原地更新它，**重启桌面端**后生效，不必重新安装。若改了 `package.json` 的依赖声明或补丁文件，仍建议在插件页移除后重新添加。改动提示词或校验规则时同步递增 `lib/policy.js` 的 `POLICY_VERSION`，让各会话在下次正常检查时重新判断，而不会批量改历史标题。
