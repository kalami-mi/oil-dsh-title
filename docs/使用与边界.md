# 使用与边界

让 DeepSeek Harness 侧边栏的会话标题跟上实际讨论内容。

## 它怎么工作

Harness 的标题服务（`sessionTitle`）把标题存成会话日志里的 `session/title` 事件，并且**同一时刻只允许一个标题提供者**。内置提供者 `session-title-llm` 只看第一条用户消息、只在第一条时触发，所以后面聊的内容再也进不了标题。

本插件是一个 bundle（补丁层），做三件事：

1. 用补丁关闭内置的 `session-title-llm`，挂上自己的提供者 `oil-dsh-title`；
2. **首条消息**：仍由标题服务自动触发，第一版标题直接按「emoji 对象｜目标」生成，替换掉“取前几个词”的占位标题。此时助手还没回答，只能依据首条消息；
3. **之后每一轮正常结束**（`turn/end`，原因为 `completed` 或 `max-tokens`）：调用标题服务的 `refresh`，由独立的一次模型请求判断保留还是更新。**首轮结束时会带着助手的回答再判断一次**（真实会话里首条消息常常是粘贴的日志或一句“继续”，只看它命名不准）；之后内容没变就不再重复。

所以一个新会话的第一轮通常有 2 次命名请求，之后平均远少于“每轮一次”。若首轮回答很快，早期那次请求会被轮次结束时的刷新取代（已发出的请求仍可能计费，会记为 `aborted`、用量未知）。

标题只通过标题服务写入，不直接改会话日志；命名请求是单独的模型调用，**不往当前会话追加任何消息**，也不影响正在进行的回答。

## 标题规则

统一结构「类别 emoji + 空格 + 对象｜目标」：恰好一个全角「｜」，两侧不留空格、不为空，最长 48 个字符，正文不再放 emoji。

| 类型 | emoji |
| --- | --- |
| 内容制作 | 🎬 |
| 工具开发 | 🧩 |
| 对比调研 | 🔎 |
| 方法整理与文档 | 📝 |
| 日程安排 | 📅 |
| 页面设计 | 🎨 |
| 环境配置 | ⚙️ |
| 一般讨论 | 💬 |

结构由程序校验，不合规的输出会带着具体原因追问模型一次；再不合规就保留原标题，不会写进一个坏标题。标题里出现邮箱、链接、盘符路径、长数字串也会被拒绝。

语义判断交给命名模型：主线有没有转移、用哪种语言。标题跟随你最近几轮的主要语言，产品名和代码名保留原文；偶尔一句外语不会让标题来回切换。提示词全文见 `lib/prompt.js`。

工作目录的**末级名称**作为弱线索发给模型（默认不复制进标题）；用户主目录和 `Documents`、`default-workspace` 这类通用目录不算项目名。不发送完整路径。新标题若以该目录名开头，会做一次确定性去重（只处理完整词，`MaplePay` 不会被 `Maple` 截断）。

## 什么时候不调用模型

| 情形 | 行为 |
| --- | --- |
| 你手动改过名 / `/title set` / `/title lock` | 永远不覆盖，零调用。进行中的命名请求会被宿主立即中止 |
| 自上次评估以来内容没有变化（且上次评估时那一轮已经看到助手的回答） | 零调用 |
| 稳定标题之后只新增“好的”“收到”“继续”等纯确认 | 最多连续 2 轮免调用，第 3 轮重新判断；夹着实质需求时不会被绕过 |
| 只有问候的开场（“你好”） | 零调用，保留占位标题 |
| 子会话（subagent） | 不命名 |
| 轮次被打断、出错、被拦截 | 不触发 |
| `/title pause` 之后 | 所有会话零调用 |

“推送”“修复”“测试”这类动作词**不**算确认，照常交给模型判断（它们通常服务于现有主线，模型会 keep）。

## 控制

在会话输入框里输入：

| 命令 | 作用 |
| --- | --- |
| `/title` 或 `/title now` | 立即按最近对话重新判断并更新，忽略“内容没变”的免调用 |
| `/title preview` | 只给候选标题，不写入 |
| `/title set <标题>` | 手动设置并固定 |
| `/title lock` / `/title unlock` | 固定当前标题 / 恢复自动命名 |
| `/title pause` / `/title resume` | 暂停 / 恢复所有会话的自动命名 |
| `/title status` | 当前标题及来源、本会话最近一次结果、累计模型用量 |

固定与解除固定直接使用宿主的语义：固定 = 写入 `user` 来源的标题事件，解除 = 让提供者再写一次。在侧边栏手动改名同样是 `user` 来源。

第一次接触一个会话时，宿主自动生成的标题和你手动设置的标题在日志里是可区分的（`fallback` / `provider` / `user`），所以与 Codex 版不同，这里**不需要**先手动 `lock` 历史标题。

## 配置

配置在 bundle 补丁 `cordis.patch.yml` 的 `oil-dsh-title` 条目里。要改动，在你自己的 profile 补丁 `~/.dsh/profiles/desktop/cordis.patch.yml` 里追加同 id 的条目。注意：**按 id 的补丁会整体替换 `config`**，要保留的字段必须一起写全。

```yaml
- id: oil-dsh-title
  config:
    provider: r4-coder              # 命名用的路由；两项必须同时填，留空则沿用会话当前的模型
    model: deepseek-v4.1-flash
    recentTurns: 5                  # 参考最近几轮
    maxInputBytes: 16384
    maxOutputTokens: 4096          # 带思考的模型会先消耗思考 token，太小会被截断（max-tokens）
    timeoutMs: 60000
    maxConfirmationSkips: 2
```

每次命名都会消耗当前账号的模型额度，标题请求一般远小于一轮正常对话。想省额度，把 `provider`/`model` 指到一个便宜的小模型。

`provider` 与 `model` 只填一项时会被忽略并告警，改用会话当前的模型。

## 数据与隐私

发送给模型的只有摘录：最近 N 轮的用户消息（每条最多约 1200 字符，头尾保留）、每轮助手最终回答的摘要（最多约 400 字符）、首条用户请求（约 600 字符）、当前标题及来源、工作目录末级名称。对话内容被放进 JSON 数据里，提示词明确要求把它当数据而不是指令。模型服务就是会话正在使用（或你在配置里指定）的那一个，不向其他服务发送。

插件不保存对话、不保存提示词。本地只有：

- `~/.dsh/oil-dsh-title/config.json`：`enabled` 开关；
- `~/.dsh/oil-dsh-title/sessions/<会话ID>.json`：评估基线（标题、已评估到的消息序号、那一轮当时是否已有回答、策略版本）；
- `~/.dsh/oil-dsh-title/logs/<会话ID>.jsonl`：状态、候选/新标题、简短理由、逐次用量与路由，超过约 96KB 自动轮转。

可用环境变量 `OIL_DSH_TITLE_DATA` 改数据目录（测试用），或用 `DSH_HOME` 移动整个 Harness 主目录。

**用量账**：`/title status` 汇总日志里的调用次数与 token，口径与宿主一致：**输入是未缓存部分，缓存命中另计、不含在输入内**（总量 = 输入 + 缓存命中 + 输出）。例如适配器收到 `prompt_tokens=900` 其中缓存 100，记为输入 800 + 缓存 100。已发出但被中止的请求（被更新的一次取代、你手动改名、插件卸载）记为 `aborted`，用量未知；模型没有返回用量的调用同样计入“用量未知”，不当作零。它只统计本插件的命名请求。

- 真实的 profile 装配器（`dsh-app-boot`）加载与桌面端同构的 profile（`dsh-base` + `dsh-web-app` + 本插件）：bundle 不被跳过、兼容性检查通过、内置提供者被关闭、本插件条目被插入、补丁无警告、用户补丁可覆盖；
- **真实端到端**（`node scripts/e2e-real-dsh.mjs`）：用桌面端自带的 `dsh` 启动器、真实运行时解析、真实智能体循环、真实 `llm-pi-ai` 适配器、真实会话存储与标题服务，只把模型换成本机的假 OpenAI 兼容服务。在隔离的 `DSH_HOME` 里用桌面端自带的 pnpm 按绝对路径安装，跑 6 轮对话：占位标题 → 首轮带回答重判 → 同主线 keep → 三次纯确认零调用 → 转向新主题更新；并核对账实相符、用量口径、没有告警、没有泄露完整路径；
- 对关键守卫做过变异检查（见 [命名与回归规范](命名与回归规范.md#变异检查)）。

**没有验证**，请按 [安装与验证](安装与验证.md) 自行确认：

- 在桌面端 **GUI** 里真实安装、热重载/重启后的实际触发，以及侧边栏标题的显示刷新（端到端用的是同一套运行时，但驱动方式是 `dsh sdk` 而不是桌面 UI）；
- 真实模型的命名质量。程序测试用的是假模型，不能代替模型评测；
- 单元/集成测试里的会话事件由脚手架按真实格式写入（格式已用你真实的会话日志核对过）；真实智能体循环由上面的端到端脚本覆盖。
- 真实安装用桌面端自带的 pnpm 在**临时 profile** 里验证过（`pnpm add <绝对路径>` 得到 `link:` 依赖，装配器能加载），但没有改动你的真实 profile。

## 限制

- 标题服务同时只允许一个提供者：装了别的标题插件会冲突，本插件重试注册后告警。
- 不做归档整理，也不做“同项目重名检查”（Codex 版有，这里暂不移植）。
- 只响应安装之后实际发生的轮次，不批量改历史会话；历史会话在下一轮结束时才按新规则整理一次（旧标题没有「｜」会做一次结构迁移）。
- 首条消息若只是问候，标题服务的自动路径会在日志里记一条 `automatic title generation failed … greeting` 的告警。这是“跳过”的正常表现，不是故障。
- `/title` 依赖 `commands` 服务；缺失时只有自动命名可用，并有一条告警。
- 命名需要联网调用模型；离线时保留原标题。
